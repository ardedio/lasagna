# upload-to-www/

**현재 운영 중인 사이트**(`lasagna.kr`)에 올리는 파일들. 새로 만드는 `site/` 와는 별개다.

---

## 지금 상태

| 방식 | 상태 |
|---|---|
| `.htaccess` | ❌ 이 서버가 읽지 않음 (확인 완료) |
| JS 리다이렉트 (`index.html`) | ✅ 적용됨 — 방문자는 자물쇠를 본다 |
| **PHP 리다이렉트 (`index.php`)** | ⏳ **PHP 사용 가능한지 확인 후 적용** |

PHP 방식이 더 낫다. **진짜 서버 리다이렉트라 검색엔진이 주소 이전으로 인정**하고,
HTML 이 전송되기 전에 처리돼서 http 상태가 존재하지 않는다.

---

## 1단계 — PHP 가 되는지 확인

1. `phptest.php` 를 `/www` 에 올린다 (이름 그대로, 바꾸지 않는다)
2. 브라우저에서 `https://www.lasagna.kr/phptest.php` 접속

| 보이는 것 | 의미 |
|---|---|
| `PHP OK` 와 서버 정보 3줄 | ✅ PHP 사용 가능 → 2단계로 |
| 코드가 그대로 보임 / 파일이 다운로드됨 | ❌ PHP 불가 → 지금의 JS 방식 유지 |

확인 후 `phptest.php` 는 **삭제한다.**

## 2단계 — `index.php` 적용 (PHP 가 될 때만)

⚠️ **순서가 중요하다.**

1. `index.php` 를 `/www` 에 올린다
2. **`https://www.lasagna.kr/index.php`** 로 먼저 접속해서 사이트가 정상인지 확인
3. 정상이면 — **기존 `index.html` 의 이름을 `index.html.bak` 으로 바꾼다**
   (지우지 말고 이름만. 문제 생기면 되돌리기 위해)
4. `https://www.lasagna.kr` 접속 → 정상 확인
5. `http://www.lasagna.kr` 접속 → https 로 넘어가는지 확인

> **3번을 빼먹으면 안 된다.** 웹서버는 보통 `index.html` 을 `index.php` 보다
> 먼저 찾는다. 둘 다 있으면 `index.html` 이 계속 서빙돼서 아무것도 안 바뀐다.

### 되돌리기

`index.html.bak` → `index.html` 로 이름을 되돌리면 즉시 원상복구된다.

## 3단계 — 302 → 301

며칠 문제없이 돌아가면 `index.php` 안의 `302` 를 `301` 로 바꿔 다시 올린다.
파일 안에 위치가 주석으로 표시돼 있다.

> 301 은 브라우저가 영구 기억하므로, 반드시 302 로 확인한 뒤에 바꾼다.

---

## 파일 목록

| 파일 | 용도 |
|---|---|
| `phptest.php` | PHP 동작 확인용. 확인 후 삭제 |
| `index.php` | PHP 리다이렉트 + 기존 사이트 (권장) |
| `index.html` | JS 리다이렉트 + 기존 사이트 (현재 적용된 것) |

`index.php` 에도 JS 블록이 남아 있다 — PHP 가 어떤 이유로 동작하지 않아도
방문자가 보호되도록 하는 이중 안전장치다.
