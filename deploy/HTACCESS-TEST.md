# `.htaccess` 가 읽히는지 확인하는 테스트

## 왜 하나

`curl` 응답 헤더는 `Server: openresty`(nginx 계열)라고 나온다. nginx 는 `.htaccess` 를
읽지 않는다. 하지만 **openresty 를 앞단 프록시로 두고 뒤에 Apache 를 돌리는 구성**도
흔하다. 그 경우 `.htaccess` 가 정상 작동한다.

카페24 인증서 화면의 `웹서버환경: Apache-ModSSL` 은 **인증서 다운로드 형식 선택**이라
서버 종류의 근거가 되지 못한다(화면 안내문에 그렇게 적혀 있다). 그리고 우리는
`.htaccess` 가 `/www` 에 올바른 이름으로 올라갔는지 **끝내 확인하지 못했다.**

그래서 추측 대신 직접 확인한다.

## 방법

> ⚠️ **2026-09-05 1차 시도는 무효였다.** 파일이 `/` 최상위에 올라갔고 이름도
> `.htaccess` 로 바뀌지 않았다. 아래 1·2번을 반드시 확인하고 진행한다.

**1. `/www` 안으로 들어간다** — 이게 핵심이다.

파일질라 오른쪽 아래 목록에서 **`www` 폴더를 더블클릭**한다.
상단 `원격 사이트:` 칸이 이렇게 바뀌어야 한다:

```
원격 사이트:  /          ← ✗ 여기 올리면 웹에서 안 보인다
원격 사이트:  /www       ← ✓ 이 상태에서 올린다
```

`index.html` · `logo.png` · `background.mp4` 가 보이면 제대로 들어온 것이다.

**2. 파일을 올리고 이름을 바꾼다**

`htaccess-TEST-only.txt` 업로드 → 우클릭 → 이름 바꾸기 → **`.htaccess`**

파일명 칸에 정확히 `.htaccess` 로 보여야 한다:

```
.htaccess           ← ✓
.htaccess.txt       ← ✗ macOS 가 확장자를 숨긴다. 다시 바꿔라
htaccessTESTonly…   ← ✗ 이름이 안 바뀐 상태
```

**3. 브라우저에서 `https://www.lasagna.kr` 을 연다** (시크릿 창 권장)

## 결과 해석

| 나온 것 | 의미 | 다음 조치 |
|---|---|---|
| **500 Internal Server Error** | Apache 가 파일을 **읽고 있다** | 테스트 파일 삭제 → `htaccess-for-cafe24-www.txt` 를 올리면 리다이렉트가 된다 |
| **사이트 정상** | 파일이 **무시되고 있다** | 테스트 파일 삭제 → 카페24에 서버 리다이렉트 요청 (`CAFE24-HTTPS.md`) |

**500 이 뜨면 좋은 신호다.** 읽고 있다는 증거고, 파일을 지우면 즉시 복구된다.

## 주의

- 500 이 뜨는 동안은 사이트가 안 열린다. **트래픽 적은 시간에** 하고 확인 즉시 지운다.
- 테스트가 끝나면 **반드시 파일을 삭제**한다. 이 파일은 오직 확인용이다.
- 최상위(`/`)가 아니라 **`/www`** 에 올린다.
