## 2. 포지셔닝 — "빠르게"를 버린다

### 폐기

> ~~AI로 가장 빠르게, 가장 잘 만든다~~

v2 프로토타입이 쓴 문장이다. **대외 메시지로는 약하다.**

- 속도는 **방어가 안 된다.** 6개월이면 따라잡힌다.
- 2026년에 "AI로 빠르게"는 차별점이 아니라 기본값이다.
- 가격 협상에서 불리하다 — 빠른 건 싸야 한다는 논리로 이어진다.

내부 미션으로는 유효하다. **밖에 걸 문장이 아닐 뿐이다.**

### 채택

> **문제를 바라보는 방식부터 다시 디자인합니다.**
> We redesign not only outcomes, but the way problems are approached.

현재 사이트에 이미 있는 문구다. 이쪽이 강한 이유:

- **관점은 따라잡기 어렵다.** 속도와 달리 복제되지 않는다.
- 클라이언트가 실제로 돈을 내는 이유와 일치한다 — 결과물만 필요하면 더 싼 곳이 있다.
- 리테이너·컨설팅으로 확장할 근거가 된다.

## 3. 구조 — 이름이 곧 방법론이다

**라자냐 = 겹겹이 쌓는 것.** 이름과 방법론이 같은 개념인데, 지금은 푸터 한 줄로만 쓰인다.
이걸 **사이트 구조 자체**로 만든다.

그리고 그 레이어가 무엇인지도 이미 적혀 있다:

> **기술과 감각, 전략과 실행**을 겹겹이 쌓아 새로운 규칙을 만들어갑니다.

네 개의 레이어가 브랜드 문구에 이미 이름 붙여져 있다. 이게 구조다.

### 페이지 구성

```
00  HERO       로고 · 영상 · 한 문장
01  관점       왜 다르게 보는가            ← 포지셔닝
02  레이어     기술 · 감각 · 전략 · 실행    ← 무엇을 하는가
03  증거       Work                       ← 결과
04  연락       
```

### 왜 이 구조가 Phase 1 에서도 버티나

일반적인 스튜디오 사이트는 **Work 가 척추**다. 그래서 작업이 적으면 텅 비어 보인다.

이 구조는 **방법론이 척추**고 Work 는 그 위에 쌓이는 층이다.
케이스가 1건이면 "아직 적다"가 아니라 **"선별했다"**로 읽힌다.
케이스가 늘어도 01·02 는 그대로다 — 03만 두꺼워진다.

### 02 레이어 섹션 — 서비스 매핑

| 레이어 | 실제로 하는 일 |
|---|---|
| **기술** Technology | AI 파이프라인 · 워크플로우 설계 · 툴 스택 |
| **감각** Sensibility | 브랜딩 · 비주얼 시스템 · 패키지 |
| **전략** Strategy | 포지셔닝 · 네이밍 · 피치덱 |
| **실행** Execution | AI 영상 · SNS 콘텐츠 · 리테이너 |

기존 서비스 목록(브랜딩 전략 · 피치덱 · 패키지 · AI 영상 · SNS)을 나열하지 않고
**네 층으로 재편**한다. 나열은 외주업체처럼 보이고, 층은 방법론처럼 보인다.

## 4. Work 정책

**케이스 상세까지 간다.** 구조는 [`CASE-PAGES.md`](CASE-PAGES.md) 에 이미 정리됨.

### 현재 인덱스 (4건)

| # | 프로젝트 | 상태 |
|---|---|---|
| 01 | 이상봉 | 스코프·카피 미입력 |
| 02 | 라이 (LIE) | 메타만 있음 |
| 03 | 시노펙스 | 케이스 페이지 초안 있음 |
| 04 | 하루하루 | 스코프·카피 미입력 |

백로그 5건(BIOLIN · DAREFIT · TFIT · COCOSPACK · DSS GROUP)은
`manifest.json` 의 `_backlog` 에 보존. 자료정리 후 복귀.

### 케이스 승인 프로세스

케이스 페이지는 대외 공개물이다. 각 페이지에 **Draft 패널**을 달아
승인 안 된 항목을 명시하고, 클라이언트 승인 후 패널을 제거한다.

- 의료(Darefit) — 의료법 §56. 치료 결과·전후 비교·환자 사례 ✕
- 화장품(BIOLIN) — 효능·성분 표현은 표시광고 규정 검토 후
- 상표 미확정 네이밍 — 클리어런스 전 노출 ✕
- 파트너사·협업자 실명, 예산, 계약 조건 — 각 사 동의 전 ✕
