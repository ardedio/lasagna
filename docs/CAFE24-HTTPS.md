# 카페24 HTTPS 적용

## 현재 상태 (2026-09-05)

| 항목 | 상태 |
|---|---|
| SSL 인증서 | ✅ 발급 완료 (유료 구매) |
| `https://` 접속 | ✅ 자물쇠 정상 |
| `http://` → `https://` 자동 전환 | ❌ **안 됨** |

`http://` 로 들어온 방문자는 여전히 **`주의 요함`** 을 본다.

---

## 원인 — 이 서버는 Apache 가 아니다

터미널 확인 결과:

```
$ curl -sI http://www.lasagna.kr/ | head -5
HTTP/1.1 200 OK
Server: openresty          ← 이것이 원인
```

**`openresty` 는 nginx 기반 서버다.** 그리고 **nginx 는 `.htaccess` 를 아예 읽지 않는다.**

`.htaccess` 는 Apache 전용 기능이다. nginx 계열에서는 파일을 어디에 두든,
안에 무엇을 쓰든 **완전히 무시된다.** 권한 문제도, 문법 문제도, 위치 문제도 아니다.
애초에 그 서버가 읽지 않는 파일이다.

> **정정:** 이 문서의 이전 버전은 카페24를 Apache 로 가정하고 `.htaccess` 업로드를
> 안내했다. 이 호스팅에서는 그 방법이 작동하지 않는다.
> `deploy/htaccess-for-cafe24*.txt` 두 파일은 **이 서버에서는 쓸 데가 없다.**

### 시크릿 창에서는 왜 됐나

그건 서버가 아니라 **크롬이 한 일**이다. 요즘 크롬은 주소를 칠 때
`https` 를 먼저 시도한다(HTTPS-First). 시크릿 창은 기록이 없어서 매번 그렇게 하고,
평소 쓰는 창에는 "이 사이트는 http" 라는 기록이 남아 있어서 바로 http 로 갔다.

즉 **서버는 처음부터 아무 전환도 하지 않고 있었다.** `curl` 이 그걸 정확히 보여준다 —
`curl` 은 브라우저 같은 자동 보정을 하지 않기 때문이다.

## 해결 — 세 가지 길

### ① 카페24에 요청한다 (정공법, 권장)

서버 설정은 카페24만 바꿀 수 있다. 고객센터에 이대로 문의하면 된다:

> 웹호스팅(lasagna.kr) 사용 중입니다.
> 유료 SSL 인증서는 정상 발급되어 `https://` 접속은 잘 됩니다.
>
> 다만 `http://` 로 접속했을 때 `https://` 로 자동 전환되지 않습니다.
> 서버가 openresty(nginx) 라서 `.htaccess` 로는 설정할 수 없는 것으로 확인했습니다.
>
> 1. 서버 쪽에서 **HTTP → HTTPS 301 리다이렉트**를 설정해 주실 수 있나요?
> 2. 또는 관리자 페이지에서 제가 직접 켤 수 있는
>    **HTTPS 자동 연결 / SSL 전용 접속** 같은 옵션이 있나요?

**문의 전에 관리자 페이지부터 한 번 보자.** `나의서비스관리` → `웹호스팅` →
`보안서버(SSL)` 근처에 위 ②번 같은 토글이 있으면 그걸 켜는 게 제일 빠르다.

### ② 임시 조치 — index.html 에 한 줄 (오늘 바로 가능)

카페24 답변을 기다리는 동안 쓸 수 있다.
`deploy/https-redirect-snippet.html` 의 `<script>` 블록을
**현재 `index.html` 의 `<head>` 바로 다음, 맨 첫 줄**에 붙여넣고 업로드한다.

**한계를 알고 쓰자:**

- 진짜 301 이 아니라서 **검색엔진은 주소 이전으로 인정하지 않는다.**
- 페이지가 http 로 한 번 열린 뒤 전환된다 — 아주 짧게 http 상태가 존재한다.
- 자바스크립트가 꺼진 환경에서는 동작하지 않는다.

그래도 **방문자 대부분에게 자물쇠를 보여준다.** ①이 해결될 때까지의 임시방편이다.

### ③ 정적 호스팅으로 옮긴다 (근본 해결)

`site/` 는 빌드 과정이 없는 순수 정적 파일이라
**Cloudflare Pages · Vercel · Netlify** 어디든 그대로 올라간다. 이쪽으로 가면:

- HTTP → HTTPS 리다이렉트가 **기본 제공** (설정할 것도 없다)
- 인증서 **자동 발급·자동 갱신** → 아래 만료 관리가 통째로 사라진다
- 전부 무료

지금 산 인증서 기간은 아까우니 다 쓰고, 만료 시점에 판단해도 된다.
자세한 건 [`DEPLOY.md`](DEPLOY.md).

## ⚠️ 인증서 만료 관리 (유료라서 중요하다)

무료 Let's Encrypt 는 서버가 알아서 갱신하지만 **유료 인증서는 자동 갱신이 안 된다.**
보통 1년짜리이고, 만료되면 사이트 전체에 **빨간 경고 화면**이 뜬다.
지금의 `주의 요함` 과는 비교가 안 되게 심각하다 — 대부분 그 자리에서 나간다.

**오늘 5분만 쓰자:**

1. 주소창 **자물쇠 클릭** → 인증서 → 유효기간에서 **만료일 확인**
2. 캘린더에 두 개:
   - 만료 **30일 전** — "lasagna.kr SSL 갱신 신청"
   - 만료 **7일 전** — "갱신 완료됐는지 확인"

30일 전에 잡는 이유: 유료 인증서는 재발급에 **심사 시간이 걸릴 수 있다.**
만료 당일에 신청하면 그 사이 사이트가 죽는다.

## 서버에 이미 있는 파일들 — 건드리지 마라

최상위(`/`)에서 숨김 파일을 켜면 이런 것들이 보인다:

```
.htaccess       66 바이트   01/20/2026
.ftpaccess      49 바이트   01/20/2026
.ftpaccess2      0 바이트
.upload_guard    0 바이트
.shelldenied     0 바이트
```

**전부 카페24가 계정 생성 때 깔아둔 파일이다.** 날짜(1월 20일)와 크기가 그 증거다.
지우거나 덮어쓰면 **FTP 접속이 막힐 수 있다.** 그대로 둔다.

혹시 `/www` 에 우리가 올린 `.htaccess` 가 있다면 **지워도 된다** — 이 서버에서는
아무 역할도 하지 않으니, 남겨두면 나중에 헷갈리기만 한다.

## 참고 — 파일질라 접속은 암호화되지 않는다

접속 로그:

```
상태: 보안되지 않은 서버입니다. TLS를 통한 FTP를 지원하지 않습니다.
```

**이 서버는 FTPS 를 지원하지 않는다.** 21번 포트 평문 FTP 만 받는다.
접속할 때마다 아이디와 비밀번호가 암호화 없이 전송된다.

할 수 있는 것:

1. 카페24에 **SFTP 지원 여부** 문의 (상품에 따라 제공된다)
2. **FTP 비밀번호를 다른 서비스와 다르게** 쓴다 ← 지금 당장 되는 실질적 방어
3. 공용 와이파이에서 파일을 올리지 않는다

방문자용 HTTPS 와는 별개 문제다. 관리자가 파일 올릴 때의 이야기다.

## 파일질라 사용 메모

- **숨김 파일 표시:** 메뉴 `서버` → `숨김 파일 강제 표시`.
  점(.)으로 시작하는 파일은 이걸 켜야 보인다.
- **웹 폴더는 `/www`** — `index.html`, `logo.png`, `background.mp4` 가 있는 곳.
  최상위(`/`)는 쓰기 금지라 업로드하면 `Permission denied` 가 난다.
- **macOS 는 확장자를 숨긴다** — 파일명을 바꿀 때 `.txt` 가 남아있지 않은지 확인.
