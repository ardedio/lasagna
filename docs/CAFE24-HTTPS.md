# 카페24 HTTPS 적용 — 단계별 가이드

웹 처음이어도 따라 할 수 있게 썼다.

```
1~2단계  SSL 인증서 발급          ✅ 완료 (유료 인증서 구매·발급됨)
2.5단계  어느 파일을 쓸지 확인     ← 30초. 여기부터 하면 된다
3단계    http → https 자동 전환   ← 파일질라로 파일 하나 업로드
```

**남은 건 사실상 3단계 하나다.** 인증서가 이미 있으니 "https 로 보냈는데
https 가 준비 안 돼서 사이트가 죽는" 위험은 없다. 다만 인증서가 어느 주소를
보호하는지에 따라 올릴 파일이 갈려서, 2.5단계 확인만 먼저 하고 넘어간다.

---

## 0단계 — 시작 전에 백업 (5분, 꼭 하자)

혹시 서버에 이미 설정 파일이 있으면 덮어쓰면 안 된다. 먼저 확인한다.

1. **파일질라를 켜고 사이트에 접속**한다.
2. 오른쪽(서버 쪽) 창에서 웹 폴더로 들어간다.
   카페24는 보통 **`/www`** 폴더다. (`public_html` 인 경우도 있다)
3. **숨김 파일을 보이게 설정한다** — 이게 핵심이다.
   `.htaccess` 는 이름이 점(.)으로 시작해서 **파일질라가 기본적으로 숨긴다.**

   > 파일질라 상단 메뉴 → **서버(Server)** → **숨김 파일 강제 표시**
   > (영문판: Server → Force showing hidden files)

4. 이제 `.htaccess` 파일이 보이는지 확인한다.
   - **있다면** → 그 파일을 내 컴퓨터로 **드래그해서 내려받아 보관한다.**
     (나중에 문제 생기면 이걸 다시 올려서 되돌린다)
     그리고 그 내용을 나에게 알려달라 — 기존 설정과 충치지 않게 합쳐줘야 한다.
   - **없다면** → 그냥 진행하면 된다. 백업할 게 없는 것뿐이다.

---

## 1~2단계 — 인증서 발급 ✅ 완료

**유료 인증서를 구매했고 발급까지 끝났다.** 이 두 단계는 건너뛴다.

다만 유료 인증서는 무료(Let's Encrypt)와 **한 가지가 다르다** — 아래
[인증서 만료 관리](#인증서-만료-관리-유료-인증서라-중요하다) 를 꼭 읽어라.

---

## 2.5단계 — 어느 파일을 쓸지 정한다 (30초)

3단계로 가기 전에 **딱 하나만 확인하면 된다.** 브라우저 주소창에 아래 두 개를
직접 쳐본다. `http` 가 아니라 **`https`** 로.

```
https://www.lasagna.kr
https://lasagna.kr          ← www 없이
```

결과에 따라 업로드할 파일이 갈린다:

| 확인 결과 | 쓸 파일 |
|---|---|
| **둘 다** 자물쇠가 뜬다 | `deploy/htaccess-for-cafe24.txt` |
| **www 만** 자물쇠, www 없는 쪽은 경고 | `deploy/htaccess-for-cafe24-www.txt` |
| **www 없는 쪽만** 자물쇠 | 알려달라 — 반대 방향 파일을 만들어주겠다 |

> **왜 갈리나:** 유료 인증서는 종류에 따라 `www.lasagna.kr` 한 개만 보호하는
> 경우가 있다. 그 상태에서 `https://lasagna.kr` 로 보내버리면 방문자에게
> **경고 화면**이 뜬다. 고치려는 문제를 오히려 만드는 셈이다.
>
> `-www` 파일은 이 경우를 위한 것으로, **모든 주소를 `www` 하나로 통일**한다.
> 인증서가 www 만 보호해도 안전하고, 검색엔진에도 주소가 하나로 잡혀서 유리하다.
> **잘 모르겠으면 `-www` 파일을 써라.** 어느 경우든 안전하게 동작한다.

---

## 3단계 — http 주소를 https 로 자동 전환

2단계까지 되면 https 로는 잘 열린다. 그런데 **누가 `http://` 로 들어오면
여전히 "안전하지 않음" 이 뜬다.** 옛날 주소는 그대로 살아있기 때문이다.
그래서 "http 로 오면 https 로 자동으로 보내주는" 설정을 넣는다.

### 3-1. 파일 준비

2.5단계에서 정한 파일을 내 컴퓨터로 받는다.

- 둘 다 자물쇠 → **`deploy/htaccess-for-cafe24.txt`**
- www 만 자물쇠 / 잘 모르겠다 → **`deploy/htaccess-for-cafe24-www.txt`**

### 3-2. 파일질라로 업로드

1. 파일질라로 서버 접속
2. 오른쪽(서버) 창에서 **`www` 폴더를 더블클릭해서 들어간다.**

   > **여기서 제일 많이 실수한다.** 접속 직후 보이는 최상위 화면에 그대로
   > 올리면 안 된다. 카페24는 최상위에 쓰기를 막아둬서
   > `Permission denied` 오류가 난다.
   >
   > 오른쪽 창 위의 **`원격 사이트`** 칸을 보고 확인한다:
   >
   > ```
   > 원격 사이트:  /          ← ✗ 여기서 올리면 오류
   > 원격 사이트:  /www       ← ✓ 이렇게 되어야 한다
   > ```
3. 왼쪽(내 컴퓨터) 창에서 받아둔 파일을 찾는다
4. 그 파일을 **오른쪽으로 드래그**해서 업로드
5. 업로드된 파일에 **우클릭 → 이름 바꾸기**
6. 이름을 정확히 이렇게 바꾼다:

   ```
   .htaccess
   ```

   **앞에 점(.)이 있고, `.txt` 는 지운다.** 이름은 이게 전부다.

7. 이름을 바꾸면 파일이 목록에서 사라진 것처럼 보일 수 있다 —
   숨김 파일이 되어서 그렇다. 0단계에서 **숨김 파일 강제 표시**를 켜뒀으면
   계속 보인다.

### 3-3. 테스트

브라우저 주소창에 **`http://`** 를 붙여서 (https 아님, http 임) 들어가 본다:

```
http://www.lasagna.kr
```

- **자동으로 `https://` 로 바뀌고 자물쇠가 뜬다** → 완료. 3-4로.
- **"리디렉션이 너무 많습니다" 오류** → 파일질라로 `.htaccess` 를 **지운다.**
  즉시 원래대로 돌아온다. 그리고 나에게 알려달라 — 카페24 서버 구성에 맞게
  고쳐주겠다.
- **아무 변화 없다** → 카페24가 `.htaccess` 를 안 쓰는 구성일 수 있다.
  이것도 알려달라.

### 3-4. 임시 → 영구로 바꾸기

테스트가 잘 되면 마지막 한 걸음이 남았다.

받아둔 파일을 메모장으로 열어서 **`R=302`** 를 **`R=301`** 로 바꾸고 저장
→ 다시 업로드 → `.htaccess` 로 이름 변경.

> `-www` 파일에는 **`R=302` 가 두 군데** 있다. 둘 다 바꿔야 한다.

> **왜 처음부터 301 을 안 쓰나:**
> 301 은 "영구 이동" 이라 **브라우저가 기억해버린다.** 설정이 틀렸을 때
> 파일을 지워도 한동안 계속 튕긴다. 302 는 기억하지 않아서 언제든
> 되돌릴 수 있다. 그래서 302 로 확인하고 → 301 로 굳힌다.

## 다 끝난 뒤 확인 목록

**`htaccess-for-cafe24.txt`** (두 주소 다 인증서가 있는 경우):

| 주소 | 기대 결과 |
|---|---|
| `http://lasagna.kr` | https 로 전환 + 자물쇠 |
| `http://www.lasagna.kr` | https 로 전환 + 자물쇠 |
| `https://lasagna.kr` | 자물쇠 |
| `https://www.lasagna.kr` | 자물쇠 |

**`htaccess-for-cafe24-www.txt`** (www 로 통일하는 경우):

| 주소 | 기대 결과 |
|---|---|
| `http://lasagna.kr` | `https://www.lasagna.kr` 로 전환 + 자물쇠 |
| `http://www.lasagna.kr` | https 로 전환 + 자물쇠 |
| `https://www.lasagna.kr` | 자물쇠 |
| `https://lasagna.kr` | 인증서가 www 만 보호하면 **여기는 경고가 남는다** |

> 마지막 줄은 고칠 수 없는 게 아니라, **인증서의 범위 문제**다.
> 방문자가 `https://` 를 직접 타이핑해서 www 없이 들어오는 경우에만 해당되고
> (링크·검색·북마크는 전부 www 로 잡힌다) 실제로는 드물다.
> 신경 쓰인다면 카페24에 **apex 도메인(`lasagna.kr`)도 인증서에 포함**해달라고
> 문의하면 된다. 유료 인증서는 추가가 가능한 경우가 많다.

자물쇠 대신 **느낌표나 경고 삼각형**이 뜬다면, 페이지 안에 아직 `http://` 로
불러오는 이미지나 영상이 남아있다는 뜻이다 (혼합 콘텐츠).
`F12` → **콘솔** 탭에 `Mixed Content` 라고 뜬 줄을 복사해서 보내주면 잡아주겠다.

## 참고 — 파일질라 자체의 보안

지금 보안 얘기를 하는 김에 하나 더. 파일질라로 접속할 때 **`FTP`** 를 쓰고
있다면, **아이디와 비밀번호가 암호화 없이 그대로 전송된다.**

파일질라 → **사이트 관리자** → 해당 사이트 → **암호화** 항목을
**"명시적 FTP over TLS 필요"** 로 바꾸면 암호화된다. 카페24는 이걸 지원한다.

접속이 안 되면 원래 설정으로 되돌리고 카페24 고객센터에
"FTPS 접속 가능한지" 문의하면 된다. 급한 건 아니지만 해두면 좋다.

## 인증서 만료 관리 (유료 인증서라 중요하다)

무료 Let's Encrypt 는 90일마다 **서버가 알아서 갱신**한다. 하지만
**유료 인증서는 자동 갱신되지 않는다.** 보통 1년짜리이고, 만료되면
사이트 전체에 **빨간 경고 화면**이 뜬다. 지금 고치려는 `안전하지 않음` 보다
훨씬 심각한 화면이다 — 대부분의 방문자가 그 자리에서 나간다.

카페24가 갱신 안내 메일을 보내주지만, 스팸함으로 가거나 놓치기 쉽다.
**직접 알림을 걸어두는 게 안전하다.**

### 지금 5분만 투자하자

1. 만료일을 확인한다. 브라우저 주소창의 **자물쇠 아이콘 클릭** →
   `인증서` 또는 `연결이 안전합니다` → 유효기간에 만료일이 있다.
2. 캘린더에 **일정 두 개**를 만든다:
   - 만료 **30일 전** — "lasagna.kr SSL 갱신 신청"
   - 만료 **7일 전** — "lasagna.kr SSL 갱신 완료됐는지 확인"
3. 갱신은 카페24 `나의서비스관리` → `보안서버(SSL)` 에서 한다.

> 30일 전에 잡는 이유: 유료 인증서는 재발급에 **심사 시간이 걸릴 수 있다.**
> 만료 당일에 신청하면 그 사이 사이트가 죽는다.

### 참고 — 나중에 갱신이 번거로우면

`docs/DEPLOY.md` 에 적어둔 **정적 호스팅**(Cloudflare Pages / Vercel /
Netlify)으로 옮기면 **인증서 발급·갱신이 완전 자동**이라 이 관리가 사라진다.
지금 구매한 인증서 기간은 다 쓰고, 만료 시점에 판단해도 늦지 않다.

## 자주 나는 오류

### `Could not open '/.htaccess' for writing: Permission denied.`

**권한 문제가 아니라 위치 문제다.** 경로 맨 앞의 `/` 가 단서다 —
`www` 폴더 안이 아니라 **최상위**에 올리려 한 것이다.

카페24는 최상위(`/`)에 쓰기를 막아둔다. 거기엔 `www`, `log` 같은 폴더만 있고,
웹 파일은 전부 `www` **안에** 들어간다. `/www/.htaccess` 가 되어야 맞다.

**해결:** 오른쪽 창에서 `www` 를 더블클릭해 들어간 뒤 다시 업로드.
`원격 사이트` 칸이 `/www` 로 바뀐 걸 확인하고 올린다.

권한을 바꾸거나 고객센터에 문의할 필요 없다. 최상위가 잠겨 있는 건 정상이다.

### 웹 폴더 이름이 `www` 가 아닌 것 같다

호스팅 구성에 따라 `public_html` · `html` · `htdocs` 인 경우도 있다.
확실한 판별법:

> **지금 사이트에 올라가 있는 파일이 보이는 폴더가 웹 루트다.**

`index.html` / `index.php`, 또는 현재 쓰는 이미지 파일들이 보이는 곳.
최상위에서 폴더를 하나씩 열어보면 금방 찾는다.

### 파일을 올렸는데 목록에서 사라졌다

정상이다. `.htaccess` 는 점으로 시작해서 **숨김 파일**로 취급된다.
0단계의 **서버 → 숨김 파일 강제 표시** 를 켜면 다시 보인다.

### 최상위에 올리다 만 파일이 남아있다

`htaccess-for-cafe24-www.txt` 같은 파일이 최상위에 보이면 지운다.
그 위치에서는 아무 역할도 하지 않고 헷갈리기만 한다.
