# 케이스 상세 페이지 — 패턴

`site/work/<id>.html` · 현재 **SYNOPEX 1건**
(BIOLIN 초안은 인덱스에서 내리면서 `drafts/work/biolin.html` 로 옮겼다 — 배포 트리 밖)

---

## 왜 JS 템플릿이 아니라 개별 HTML 인가

케이스 페이지를 JSON + JS 렌더링으로 짜면 DRY 하지만 **크롤러가 빈 페이지를 본다.**
케이스 상세를 만드는 이유의 절반이 검색 유입이라 그 구조는 목적과 충돌한다.

그래서 페이지당 실제 HTML 문서 하나. 7개까지는 이 방식이 옳다.
공통 껍데기가 중복되지만, 중복의 대가보다 SEO·속도·`file://` 동작이 크다.
스타일은 `css/case.css` 하나로 공유하므로 디자인 변경은 한 곳에서 끝난다.

## 새 케이스 추가하는 법

**1) 페이지 복사**

```bash
cp site/work/synopex.html site/work/tfit.html
```

`<body data-case="tfit">` 을 바꾸고, 아래를 채운다 — 구조는 건드리지 않는다.

| 블록 | 내용 |
|---|---|
| `<title>` / `og:*` | 프로젝트명 + 한 줄 |
| `.chero__eyebrow` | 클라이언트 · 카테고리 |
| `.chero__name` | 프로젝트명 |
| `.chero__lede` | 2줄. 무엇을 했는지가 아니라 **무엇을 풀었는지** |
| `.facts` | Client / Scope / Format(또는 Market) / Status |
| `01 과제` | 문제 진단 3문단. 카테고리의 구조적 문제 → 이 브랜드에 왜 치명적인지 → 진짜 과제 |
| `.pull` | 한 줄. 캠페인 라인이거나 전략 명제 |
| `02 접근` | MOVE 3개. 각 하나의 판단만 |
| `03 산출물` | 5행 내외 |
| `.strip` | 스틸 2컷 |
| `.pager` | prev / next 갱신 — **양쪽 다** 고쳐야 한다 |

**2) 인덱스에 연결**

`site/assets/kv/manifest.json` 의 해당 항목:

```json
"page": "work/tfit.html"
```

`null` 이면 홈에서 링크 없이 `준비 중` 칩만 붙는다 — 404 로 보내지 않는다.

**3) 키비주얼**

`site/assets/kv/` 에 `kv-<id>.jpg` (히어로) + 스트립용 2컷.
없으면 `_placeholder.svg` 로 폴백하므로 페이지는 깨지지 않는다.

현재 필요한 파일:

```
kv-synopex.jpg kv-synopex-ep1.jpg kv-synopex-ep3.jpg
```

**4) 승인 표시**

페이지 하단 `<aside class="draft">` 에 **아직 확인 안 된 것**을 적는다.
클라이언트 승인이 끝나면 `<aside>` 통째로 지운다. 승인 전에 지우지 않는다.

## 카피 원칙

**진단 → 판단 → 근거.** 과정 나열은 케이스가 아니다.
"무엇을 만들었다"가 아니라 "왜 그렇게 판단했다"를 쓴다. 클라이언트가 읽고
*이 사람들은 내 문제를 이해한다* 고 느껴야 다음 문의가 온다.

**형용사 금지.** "혁신적인", "감각적인" 은 아무 정보가 없다. 동사와 명사로 쓴다.

**수치는 확인된 것만.** KPI·예산·매출은 클라이언트 승인 전 노출 금지.

## 컴플라이언스

케이스 페이지는 **대외 공개물**이다. 홈보다 기준이 높다.

- **의료** (Darefit 등) — 의료법 §56. AI 비주얼은 기전·무드까지.
  **치료 결과 · 전후 비교 · 환자 사례 표현 금지.** 케이스 작성 전 사전심의 기준 재확인.
- **화장품** (BIOLIN) — 효능·성분 표현은 화장품 표시광고 규정 검토 후에만.
  현재 BIOLIN 페이지에는 제품 표현이 **하나도 없다.** 그 상태를 유지하는 게 안전하다.
- **상표 미확정 네이밍** — KIPRIS · J-PlatPat · 클래스 3/5 클리어런스 전 노출 ✕.
  변리사 확정 전까지 후보명은 페이지에 올리지 않는다.
- **파트너사·협업자 실명, 예산, 계약 조건** — 각 사 동의 전 노출 ✕.

SYNOPEX 페이지와 보관 중인 BIOLIN 초안 모두 위 항목을 **의도적으로 비워뒀고**,
무엇을 왜 뺐는지는 각 페이지의 Draft 패널에 적혀 있다.
